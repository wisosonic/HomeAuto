# HomeAuto: notes for Claude (read this first)

Smart-home system on a **Raspberry Pi 5**: Python backend (sensor drivers + FastAPI) and a React
dashboard. Repo: https://github.com/wisosonic/HomeAuto (branch `main`). Dev machine is Windows 11
(PowerShell + Git Bash); deployment target is Raspberry Pi OS.

## Hardware (what the user owns)

Pi 5, breadboard, jumper wires (male-male, female-male), and a sensor kit. **No resistors, capacitors
or any other parts.** Do not propose designs that need them (voltage dividers, LED resistors, pull-ups).

| Sensor | Status |
|---|---|
| PIR HC-SR501, sound (red LM393), flame, IR obstacle FC-51, rain (MH-RD), vibration (blue) | **Implemented** (digital DO pin) |
| DS1302 RTC, KY-008 laser, 2 LEDs (blue/green), 433 MHz TX/RX pair | Not started |
| HC-SR04 ultrasonic | Blocked: echo pin is 5V, Pi GPIO is not 5V-tolerant, needs a divider. Check if it is an HC-SR04P. |
| Soil moisture probe | Only the probe seen, comparator board may be missing |
| Line-tracking IR module, another blue LM393 board (3+4 pins, unidentified), MQ-type gas sensor ("Flying Fish") | Not started; gas sensor's DO would be 5V if powered at 5V |

Hardware constraints that drive design:
- **Pi has no ADC.** Only the DO (digital) pin of the modules is usable; leave AO unconnected.
- **GPIO is 3.3V, not 5V-tolerant.** Power modules from 3.3V except the PIR (5V supply, 3.3V output).
- LEDs without resistors: drive with low-duty PWM (~10-20%), never solid.
- Use `gpiozero` + `lgpio` (RPi.GPIO does not work on Pi 5).

## Architecture

```
backend/homeauto/
  base.py        DigitalSensor: gpiozero DigitalInputDevice wrapper; active_state, debounce,
                 SensorEvent, listeners (called on gpiozero threads), snapshot(); enable()/disable()
                 create/close the gpiozero device (disable releases the GPIO pin)
  sensors/       one tiny subclass per sensor (kind, active_state, bounce_time); SENSOR_TYPES
                 registry + create_sensors(); keys match pinmap.DEFAULT_PINS
  pinmap.py      the ONLY place BCM pins are defined (pir 17, sound 27, flame 22,
                 ir_obstacle 23, rain 24, vibration 25); also BCM_TO_PHYSICAL and POWER_PINS
  wiring.py      build_wiring(): pin map + breadboard columns for the Wiring page;
                 MODULE_INFO holds each module's label, VCC source and signal-pin label
  store.py       SQLite: events table (add/recent/clear) + sensor_settings (enabled flags);
                 locked, check_same_thread=False
  auth.py        AuthStore (same SQLite file, own connection): users, roles, role_permissions, sessions.
                 PERMISSIONS dict = the ONLY place permissions are defined (code decides what exists, roles
                 are stored sets of them). scrypt passwords (stdlib), opaque bearer tokens (only the SHA-256
                 is stored), login lockout, last-manager guard. AuthError(status, message) -> JSON via api.py
  schedule.py    ScheduleStore (rules table, same SQLite file). A rule only HOLDS its sensors on during
                 [start, end); effective state = saved on/off setting (sensor_settings) OR held. api.py's
                 reconcile() applies it (startup, every rule/toggle change, 1 s background tick), so sensors
                 fall back to their saved setting when a rule ends. Disabling a held sensor -> 409.
                 Permissions schedules.view / schedules.manage; times are epoch seconds
  hub.py         EventHub: bridges gpiozero threads -> asyncio via call_soon_threadsafe
  api.py         create_app(mock=, db_path=); REST + /ws; serves frontend/dist if it exists
backend/tests/   pytest, hardware-free (gpiozero MockFactory)
backend/demos/watch_all.py   print events from real sensors
frontend/        Vite + React (JSX, no TS). src/useSensors.js = WebSocket (auto-reconnect) + REST.
                 useAuth.js = login state (token in localStorage, `can(perm)`); api.js adds the Bearer header
                 and calls the 401 handler; LoginPage/AccountPage/UsersPage (users + roles admin).
                 Hash routing in App.jsx (#/ dashboard, #/sensors enable/disable, #/wiring, #/users, #/account;
                 each page lists the permissions it `needs`). components/WiringPage.jsx +
                 WiringDiagram.jsx draw the breadboard diagram from GET /api/wiring (not static)
docs/            wiring.png/.svg, generated by docs/make_wiring.py
WIRING.md        wiring guide (pins, breadboard columns, safety checklist)
runner.bat       Windows: backend (mock, background) + Vite (foreground) in ONE console window;
                 scripts/stop-homeauto.ps1 frees a leftover backend on port 8000 at start and exit
runner.sh        Pi: builds UI if stale, serves UI + API on one port (0.0.0.0:8000)
```

API: `GET /api/info` (public), `/api/wiring`, `/api/sensors`, `/api/sensors/{name}`, `/api/events?limit=&sensor=`,
`DELETE /api/events[?sensor=]` (clear history), `PUT /api/sensors/{name}/enabled` `{enabled}` (persisted;
restored at startup), `POST /api/sensors/{name}/simulate` (mock mode only: 403 otherwise, 409 if the
sensor is disabled), WebSocket `/ws` (the client's FIRST message must be `{"type":"auth","token"}`; then the server
sends `{"type":"snapshot"}`, then `event`, `sensor_state`, `events_cleared`; the hub carries plain dicts).
Auth: `POST /api/auth/login|logout|password`, `GET /api/auth/me`, users `GET/POST /api/users`,
`PATCH/DELETE /api/users/{username}`, roles `GET/POST /api/roles`, `PUT/DELETE /api/roles/{name}`,
`GET /api/permissions`. Everything but `/api/info` and login needs `Authorization: Bearer`.

Authorisation: every route declares its permission with `Depends(require("x.y"))` in api.py (docs in the module
docstring list them). **A new endpoint must get a `require(...)`**, and a new permission goes in
`auth.PERMISSIONS` (the admin role is topped up with it at startup; add it to operator/viewer in `DEFAULT_ROLES`
only affects fresh databases). One role per user. Roles: `admin` (locked, always everything), `operator`, `viewer`
(built-in, cannot be deleted). The last active user holding `users.manage` can never be removed/disabled/demoted.

Adding a new digital sensor: subclass `DigitalSensor` in `sensors/<name>.py`, register it in
`sensors/__init__.py` (`SENSOR_TYPES`), add its pin to `pinmap.py`, add icon/labels in
`frontend/src/components/SensorCard.jsx`, describe it in `frontend/src/sensorInfo.js` (summary,
what it reports, good for, limits: shown on the Sensors page), add its entry to `MODULE_INFO` in `wiring.py` (the Wiring page
updates itself), add a test, and update `WIRING.md` and `docs/make_wiring.py` (static PNG used on GitHub).
Non-digital devices (RTC, RF, laser, LEDs) will not fit `DigitalSensor`; they need their own base
or module (actuators also need control endpoints and authentication).

## Frontend conventions

- **User confirmations use SweetAlert2 (swal), notifications use toastr** (user requirement). Always go through
  `frontend/src/notify.js`: `confirmDialog({title, text, confirmText, danger})` -> Promise<boolean>, and
  `notify.success/error/warning/info(message)`. Never use `window.confirm` / `alert`. toastr needs jQuery
  (installed as its dependency; works with Vite as-is).
- Runtime UI checks: drive headless Edge through CDP from Node (Node 24 has a global `WebSocket`):
  launch `msedge --headless=new --remote-debugging-port=PORT`, then `Runtime.evaluate` clicks and
  `Page.captureScreenshot`. See how it was done in the session scratchpad if needed.

Backend dev server manually: `HOMEAUTO_MOCK=1 uvicorn homeauto.api:app --reload` (docs at /docs).
Env vars: `HOMEAUTO_MOCK=1`, `HOMEAUTO_DB` (default `homeauto.db`), `HOMEAUTO_CORS`
(default `http://localhost:5173`), `HOMEAUTO_STATIC` (override UI dir), `HOMEAUTO_ADMIN_PASSWORD` (password for the
first-run `admin` user; if unset a random one is generated and **printed once** in the backend console, with
runner.bat that is the single shared window. It is only used while the users table is empty; to reset a lost
password with no other admin, delete the `users` rows or the db file).

## Decisions and polarity assumptions

- PIR is active-HIGH. Sound, flame, IR obstacle, rain, vibration are assumed **active-LOW** (LM393
  modules pull DO low on detection). **None of this has been verified on real hardware.** The
  vibration module is the least certain (may be a tilt/reed switch); fix with `active_state=True`.
- A sensor's detection count and last event are **derived from the stored event history**: rebuilt from
  SQLite at startup (`restore_stats`) and reset when events are cleared (`reset_stats`, also in the
  frontend's `events_cleared` handler). Don't keep separate in-memory counters that can drift from the log.
- Debounce times in the sensor classes are guesses to tune on hardware.
- PIR 5V comes straight from Pi pin 2 to its VCC column (no 5V breadboard rail), to avoid ever
  mixing rails. Everything else uses the 3.3V rail.
- Pin order drawn in the wiring diagram (VCC, signal, GND) is illustrative; the user must match each
  module's silkscreen labels.
- Frontend is plain JS/JSX; backend serves the built UI in production so the Pi runs one process.

## Gotchas learned

- `gpiozero` MockFactory pins start LOW, which reads as *active* for active-low sensors. Drive them
  HIGH first (api.py lifespan and tests do this).
- In `.bat` files, `->` in `echo` is parsed as a redirect. Don't use `>` in echo text.
- From PowerShell, run batch files as `.\runner.bat` (plain `runner.bat` / `cmd /c runner.bat` is not
  found; NoDefaultCurrentDirectoryInExePath). In Git Bash use `bash runner.sh` or PowerShell for `.bat`.
- `uvicorn --reload` = supervisor + worker; the **worker inherits the listening socket**, so killing only the
  supervisor leaves port 8000 held. `scripts/stop-homeauto.ps1` kills python procs matching `homeauto.api`,
  the listener owner and its children (it checks `http://127.0.0.1:8000/api/info` first so it never kills a foreign
  app; use 127.0.0.1, PowerShell tries IPv6 for `localhost`). Ctrl+C in runner.bat shows the usual
  "Terminate batch job (Y/N)?" prompt; closing the window kills both servers.
- Don't copy `backend/.venv` or `frontend/node_modules` between Windows and the Pi (platform-specific).
- `.gitattributes` forces LF for `*.sh` and CRLF for `*.bat`; CRLF breaks `runner.sh` on the Pi.
- Bash tool: very long commands with several heredocs containing quotes failed with "unexpected EOF"
  and wrote nothing. Use the Write/Edit tools for big files (Read them first if they already exist).
- Writing files from Python on Windows: pass `encoding='utf-8'` (default cp1252 chokes on `●`, `·`, `→`).
- Screenshot the SPA with Edge headless: add `--virtual-time-budget=6000` so fetches finish, e.g.
  `msedge --headless=new --window-size=1200,1750 --virtual-time-budget=6000 --screenshot=out.png http://localhost:8766/#/wiring`.
- Render the wiring PNG with Edge headless:
  `msedge --headless=new --screenshot=docs\wiring.png --window-size=1320,900 file:///.../docs/wiring.svg`
  (after `python docs/make_wiring.py`). Use `curl.exe` (not the PowerShell alias) for HTTP checks.
- `pytest` prints a harmless httpx/starlette deprecation warning.
- Tests log in through `tests/test_api.py::session()` (bootstrap admin) and open the socket with `ws_connect()`
  (sends the auth message). A bare `TestClient`/`websocket_connect` now gets 401 / a 4401 close.
- WebSocket close codes: 4401 = not authenticated, 4403 = authenticated but no `sensors.view`. The frontend stops
  reconnecting on both (retrying with the same token cannot succeed).
- Heredocs through the Bash tool eat backslashes in Windows paths inside JS/Node scripts; write such scripts with
  the Write tool and use forward slashes.
