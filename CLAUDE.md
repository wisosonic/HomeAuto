# HomeAuto: notes for Claude (read this first)

Smart-home system on a **Raspberry Pi 5**: Python backend (sensor drivers + FastAPI) and a React
dashboard. Repo: https://github.com/wisosonic/HomeAuto (branch `main`). Dev machine is Windows 11
(PowerShell + Git Bash); deployment target is Raspberry Pi OS.

## Hardware (what the user owns)

Pi 5, breadboard, jumper wires (male-male, female-male), and a sensor kit. **No resistors, capacitors
or any other parts.** Do not propose designs that need them (voltage dividers, LED resistors, pull-ups).

| Sensor | Status |
|---|---|
| PIR HC-SR501, sound (red LM393), flame, IR obstacle FC-51, rain (MH-RD), vibration (blue) | **Implemented** (digital DO pin) |
| DS1302 RTC, KY-008 laser, 2 LEDs (blue/green), 433 MHz TX/RX pair | Not started |
| HC-SR04 ultrasonic | Blocked: echo pin is 5V, Pi GPIO is not 5V-tolerant, needs a divider. Check if it is an HC-SR04P. |
| Soil moisture probe | Only the probe seen, comparator board may be missing |
| Line-tracking IR module, another blue LM393 board (3+4 pins, unidentified), MQ-type gas sensor ("Flying Fish") | Not started; gas sensor's DO would be 5V if powered at 5V |

Hardware constraints that drive design:
- **Pi has no ADC.** Only the DO (digital) pin of the modules is usable; leave AO unconnected.
- **GPIO is 3.3V, not 5V-tolerant.** Power modules from 3.3V except the PIR (5V supply, 3.3V output).
- LEDs without resistors: drive with low-duty PWM (~10-20%), never solid.
- Use `gpiozero` + `lgpio` (RPi.GPIO does not work on Pi 5).

## Architecture

```
backend/homeauto/
  base.py        DigitalSensor: gpiozero DigitalInputDevice wrapper; active_state, debounce,
                 SensorEvent, listeners (called on gpiozero threads), snapshot()
  sensors/       one tiny subclass per sensor (kind, active_state, bounce_time); SENSOR_TYPES
                 registry + create_sensors(); keys match pinmap.DEFAULT_PINS
  pinmap.py      the ONLY place BCM pins are defined (pir 17, sound 27, flame 22,
                 ir_obstacle 23, rain 24, vibration 25)
  store.py       SQLite event history (locked, check_same_thread=False)
  hub.py         EventHub: bridges gpiozero threads -> asyncio via call_soon_threadsafe
  api.py         create_app(mock=, db_path=); REST + /ws; serves frontend/dist if it exists
backend/tests/   pytest, hardware-free (gpiozero MockFactory)
backend/demos/watch_all.py   print events from real sensors
frontend/        Vite + React (JSX, no TS). src/useSensors.js = WebSocket (auto-reconnect) + REST
docs/            wiring.png/.svg, generated by docs/make_wiring.py
WIRING.md        wiring guide (pins, breadboard columns, safety checklist)
runner.bat       Windows: backend (mock) + frontend dev server in two windows
runner.sh        Pi: builds UI if stale, serves UI + API on one port (0.0.0.0:8000)
```

API: `GET /api/info`, `/api/sensors`, `/api/sensors/{name}`, `/api/events?limit=&sensor=`,
`POST /api/sensors/{name}/simulate` (mock mode only, 403 otherwise), WebSocket `/ws`
(first message `{"type":"snapshot"}`, then `{"type":"event", ...}`).

Adding a new digital sensor: subclass `DigitalSensor` in `sensors/<name>.py`, register it in
`sensors/__init__.py` (`SENSOR_TYPES`), add its pin to `pinmap.py`, add icon/labels in
`frontend/src/components/SensorCard.jsx`, add a test, update `WIRING.md` and `docs/make_wiring.py`.
Non-digital devices (RTC, RF, laser, LEDs) will not fit `DigitalSensor`; they need their own base
or module (actuators also need control endpoints and authentication).

## Commands

```powershell
# backend tests (Windows): from backend/
.venv\Scripts\python -m pytest -q          # 12 tests, no hardware needed
# run everything on Windows (mock GPIO)
.\runner.bat            # or: .\runner.bat nobrowser
# on the Pi
./runner.sh             # real GPIO;  --mock for fake;  --rebuild to force UI build
```
Backend dev server manually: `HOMEAUTO_MOCK=1 uvicorn homeauto.api:app --reload` (docs at /docs).
Env vars: `HOMEAUTO_MOCK=1`, `HOMEAUTO_DB` (default `homeauto.db`), `HOMEAUTO_CORS`
(default `http://localhost:5173`), `HOMEAUTO_STATIC` (override UI dir).

## Decisions and polarity assumptions

- PIR is active-HIGH. Sound, flame, IR obstacle, rain, vibration are assumed **active-LOW** (LM393
  modules pull DO low on detection). **None of this has been verified on real hardware.** The
  vibration module is the least certain (may be a tilt/reed switch); fix with `active_state=True`.
- Debounce times in the sensor classes are guesses to tune on hardware.
- PIR 5V comes straight from Pi pin 2 to its VCC column (no 5V breadboard rail), to avoid ever
  mixing rails. Everything else uses the 3.3V rail.
- Pin order drawn in the wiring diagram (VCC, signal, GND) is illustrative; the user must match each
  module's silkscreen labels.
- Frontend is plain JS/JSX; backend serves the built UI in production so the Pi runs one process.

## Gotchas learned

- `gpiozero` MockFactory pins start LOW, which reads as *active* for active-low sensors. Drive them
  HIGH first (api.py lifespan and tests do this).
- In `.bat` files, `->` in `echo` is parsed as a redirect. Don't use `>` in echo text.
- From PowerShell, run batch files as `.\runner.bat` (plain `runner.bat` / `cmd /c runner.bat` is not
  found; NoDefaultCurrentDirectoryInExePath). In Git Bash use `bash runner.sh` or PowerShell for `.bat`.
- Closing the backend window of `runner.bat` can orphan the uvicorn `--reload` child on port 8000.
  Kill by port: `Get-NetTCPConnection -LocalPort 8000 | % { Stop-Process -Id $_.OwningProcess -Force }`.
- Don't copy `backend/.venv` or `frontend/node_modules` between Windows and the Pi (platform-specific).
- `.gitattributes` forces LF for `*.sh` and CRLF for `*.bat`; CRLF breaks `runner.sh` on the Pi.
- Render the wiring PNG with Edge headless:
  `msedge --headless=new --screenshot=docs\wiring.png --window-size=1320,900 file:///.../docs/wiring.svg`
  (after `python docs/make_wiring.py`). Use `curl.exe` (not the PowerShell alias) for HTTP checks.
- `pytest` prints a harmless httpx/starlette deprecation warning.
